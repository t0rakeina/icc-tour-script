# Workshop Cue — GitHub Pages 版 公開手順（2026-10-21 JST）

## 中身
- `site/`    … そのまま公開できる完成品（ビルド済み）。**普段はこれだけ使えばOK**
- `source/`  … 修正・再ビルド用のソース（Vite + React）。`npm install` → `npm run build` で `dist/` ができる

## 1. 公開する（GitHub Pages）
1. GitHubで新しいリポジトリを作る（例：`icc-tour-script`）。
2. `site/` の**中身**（`index.html`、`assets/`、`sw.js` など。`.nojekyll` も含む）をリポジトリに置く。
   - 置き場所は、リポジトリの直下でも `docs/` フォルダの中でもOK。
   - ※ `site/` フォルダ自体ではなく、**中のファイル**を置く。
3. リポジトリの Settings → Pages で、公開元をブランチ（`main`）にし、フォルダを「直下」または「/docs」から選ぶ。
   - 画面の名称は変わることがあります。GitHub公式の最新手順を確認してください。
4. 数分後に `https://（ユーザー名）.github.io/（リポジトリ名）/` で開けます。

アプリ内のパスはすべて相対指定なので、リポジトリ名やフォルダが変わっても動きます。

## 2. iPadに入れる
1. iPadの**Safari**で上のURLを開く。**オンライン**で、一度最後まで表示させる。
2. 共有ボタンから「ホーム画面に追加」を選ぶ（画面の表記はiPadOSのバージョンで違うことがあります）。
3. **これからは必ずホーム画面のアイコンから起動する。**

## 3. 本番前の点検（おすすめ）
- 台本を読み込み、本番画面まで進めておく。
- 機内モードにして、ホーム画面のアイコンから起動できるか確認する。
- 自動ロックで画面が暗くならないか、本番と同じ長さで確認する。
- 予備の端末（別のiPadやスマホ）にも同じ状態を作る。
- 台本の元データ（スプレッドシート）は必ず残す。端末内データが消えても貼り付け直せば復旧できる。

## 4. 更新するとき
1. `site/` の中身を新しいものに差し替えて公開する。
2. iPadでは、**オンラインでアプリを開く → アプリを完全に閉じる → もう一度開く** で新しい版になる（1回目は古い版が出ることがある）。

## 注意
- **URLが変わると、端末内の保存データは引き継がれません**（旧URL＝別の保存場所）。移行後は、スプレッドシートから貼り付け直してください。
- **サイトは誰でも見られます**（URLを知っていれば）。台本は端末内にだけ保存され、サイトのファイルには入りません。ただし、アプリ初期のサンプル進行表（「ICC アニュアル2026 ギャラリーツアー」の例文）はソースに含まれていて、公開すると誰でも読めます。気になる場合は、サンプルを差し替えてから公開してください。
- 無料プランのGitHub Pagesは、公開リポジトリが基本です（公式ドキュメント）。非公開リポジトリでも、サイト自体は公開されます。
